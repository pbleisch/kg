# 0007 - MCP Server (Model Context Protocol)

**AMENDED 2026-08-30 by [0027](0027-delete-index-and-daemon.md).** The MCP server does
not connect to a daemon — there is none, and there is no gRPC-over-UDS API. It calls the
library directly, over stdio to its own caller. The decision to speak MCP over stdio is
unchanged.


Status: Proposed

Date: 2026-02-01

Authors: Paul

Context
-------
The MCP mode exposes kg operations as a structured protocol for agents and external processes. Decisions to record: API surface (methods), transport (HTTP/gRPC/unix socket/stdio), message formats (JSON/protobuf/JSON-RPC), authentication/authorization, versioning, error model, and discovery.

Decision
--------
Status: Decided

Decision:
- MCP standard: The MCP server will implement the MCP standard/message formats to maximize compatibility with existing agent tooling and specifications.
- Transport: Support only the stdio transport initially (MCP over stdio). No network/UDS/gRPC transport for MCP in v1—agents connect to the MCP server over stdio as per the MCP standard.
- MCP server role: Implement a thin adapter that translates MCP stdio requests to daemon operations. The MCP server acts as an MCP-facing process and connects to the daemon via the daemon's gRPC-over-UDS API to execute queries and mutations.
- CLI shim and debugging: Provide `kg mcp` and `kg debug` CLI subcommands to invoke MCP operations locally and to proxy requests to the MCP server for debugging. `kg` remains the primary debugging shim.
- Versioning and errors: Adhere to MCP versioning where applicable and use structured error responses; CLI outputs will mirror TOON structured errors for consistency.
- Auth: stdio transport implies local agent execution; document token/TLS-based auth for future remote scenarios and rely on OS-level permissions for local use.

Consequences:
- Aligns kg with the MCP ecosystem and keeps the initial implementation simple by using stdio. Requires implementing an adapter bridge between MCP stdio and the daemon's gRPC API.
- Testing should validate the MCP stdio behavior and the correctness of delegation to the daemon.
